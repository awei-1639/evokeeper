# W1 论文精读指南（5 篇）

> 读法：每篇先带着"产出问题"读（边读边回答），读完必须产出一个**面向 EvoKeeper 的设计决策**并写入 docs/design-notes.md。
> 时间预算：每篇 2-3 小时（略读摘要与方法图 → 精读核心章节 → 做产出）。
> 提醒：arXiv:2609.06396（MetaRSI）是 2026-09-06 的新报告，未经同行评议，**把它当设计语言用，不当结论引用**。

---

## 1. MetaRSI / RSI²（arXiv:2609.06396）—— 总纲，最优先读

**定位**：把自我改进统一为 Loop Kernel（反馈→学习信号→提出改动→验证器裁决→回流），三个可写面：Data-RSI / Harness-RSI（Prompt/Skill/MCP/Tools/Memory 五槽位）/ Model-RSI；元层修订改进策略本身。

**带着这些问题读**：
1. Loop Kernel 的五个环节分别对应 EvoKeeper 的哪个模块？（预期：映射到我们的轨迹→整理→门禁→发布闭环）
2. 五条定律中，Law 1（验证器决定边界）和 Law 4（可信度由不可写表面衡量）如何约束我们的门禁与灰度设计？
3. Harness-RSI 的五个槽位，我们 v1 只开放哪几个？（预期：Skill + Memory + Prompt；MCP/Tools 冻结）

**产出物**：一张"EvoKeeper ↔ Loop Kernel"映射表；确定 v1 开放的槽位清单。

## 2. Agent Workflow Memory（AWM）—— 经验从哪来

**定位**：从 Agent 的成功执行轨迹中归纳出可复用的工作流（workflow），注入后续任务的上下文，多基准显著提升。

**问题**：
1. 它归纳 workflow 的触发条件与粒度是什么？（trajectory-level vs step-level）
2. 我们睡眠整理管线（W5）的聚类粒度应该学它还是改它？中文技术问答场景的差异在哪？
3. 它如何避免归纳出"过拟合到历史轨迹"的工作流？（对照我们的 holdout 设计）

**产出物**：睡眠整理管线的流程草图（聚类 → 归纳 → 候选）。

## 3. Voyager —— 技能库的组织形态

**定位**：Minecraft 环境 Agent，成功技能以可执行代码存入 Skill Library，含描述索引、复杂度递增的课程机制。

**问题**：
1. 技能的"描述—内容—检索键"三元结构怎么设计的？
2. 我们技能是自然语言 .md 而非代码，检索键用什么？（预期：embedding + 标签切片）
3. 它的"自动课程"思想能否用于我们选择"优先归纳哪类失败"？

**产出物**：技能记忆（procedural memory）的文件格式与索引设计草案。

## 4. Reflexion —— 反思机制的基础范式

**定位**：失败后生成语言化自我反思存入记忆，下次尝试注入。开创"verbal RL"。

**问题**：
1. 它的 Actor / Evaluator / Self-Reflection 三角色如何对应我们系统的组件？
2. 论文指出反思 buffer 过大会被矛盾建议淹没——这对我们"记忆无限增长"的风险给出什么警示？（对应 LightMem 的压缩动机）
3. 我们的"失败判别"与它的 Evaluator 有何本质区别？（预期：它有明确成功信号，我们靠反应信号推断）

**产出物**：失败判别规则 v1 的修订意见（对照计划书 §5.1）。

## 5. Mem0（arXiv:2504.19413）—— 记忆怎么写

**定位**：生产级记忆 API：从对话增量抽取候选记忆，LLM 决策 ADD/UPDATE/DELETE/NONE 四操作；图变体（FalkorDB）；LoCoMo 上 +26%，p95 延迟 -91%，token 成本 -90%。

**问题**：
1. 四操作的判定 prompt 怎么组织？（W3 记忆层直接参考）
2. 它把"记忆抽取"放在对话内还是对话后？与我们的睡眠整理如何分工？（预期：它在线抽取单条事实，我们离线归纳跨轨迹模式——两层并存）
3. 它的延迟/成本工程（-90% token）用了什么手段？对照我们 llm-router 的缓存设计。

**产出物**：记忆层 v1 的写路径设计（含四操作判定规则）。
